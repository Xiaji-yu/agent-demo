## 1. 已实证的问题

### H1｜【已复现（主代理亲复现）】unzip 通配符 archive 名使条目预扫描空转——条目表全部防线失效、0777 条目存活

**证据链**（四环全部实证，复现脚本落盘目标为 /tmp 隔离临时目录，已清理）：

1. 白名单放行通配符操作数（`agentcore/workspace/runner.py:917-926` 只校验 `-` 开头的开关与 `-d`；`evil*.zip` 不以 `-` 开头）——实测 `permitted('unzip', ['-o','-d','out','evil*.zip'], root=ws) -> (True, '')`；
2. 扫描侧对打不开的路径**不拒且返回空表**（`runner.py:1060-1064` `except Exception: return None, []`）——实测 `_zip_scan(ws/'evil*.zip') -> (None, [])`；
3. unzip 自身对 archive 参数做 glob 展开（本机 Info-ZIP 实证多包全处理）——`run()` 输出 `Archive: evil1.zip / extracting: out/evil.sh`；
4. `run()` 因 `entry_names=[]` 使 `strip_entry_exec_bits` 空操作（`runner.py:1340-1357`）——**落盘 `out/evil.sh` 权限 0o777**（比上轮报告的 0755 形态更直接）。

**影响**：medium 档「构造压缩包 → 通配符解压 → `run_build_script` 继承完整进程环境执行」链重组成功，且比被修的两个 flag 更简单（条目直接命名 `evil.sh`，无需展平）；`_zip_scan` 的穿越/绝对路径/`.git*` 拦截同在此门一并失效。前提与在库两次 H1 定级先例一致（medium `run_command` + superuser + 注入诱导）。注意：落盘通路是 `fs.write`（content: str 无字节过滤，tar 头全 ASCII 可构造），**不是**多份在库文档所写的「curl 拉包」（curl 白名单 GET-only 无落盘通路，见 L10）。

**修复建议**：① `run()` 内对 `_unzip_archive_operand`/`_tar_archive_operand` 的返回值检查 glob 元字符（`*?[`）即拒；② `_zip_scan` 区分「路径不存在」（拒绝）与「存在但非 zip」（保留现语义让 unzip 自报错）；③ 回归负例：3 种 glob 形态 permitted 负例 + 端到端「真实 evil.zip + 通配符调用 → 拒绝且零落盘」。tar 侧同型通配门已证伪（GNU/busybox tar 均不对 `-f` 操作数 glob），但①建议两侧同做以绝后患。

### M1｜【已复现（线1）】local.py：目录级工作区检查可通过文件级 symlink 旁路

`agentcore/skills/local.py:85-99` 只对**目录** resolve 检查，`:124` 加载循环对单个 `.py` 无任何检查（grep 全文件无 `is_symlink`）。线1 实验复现：`data/skills/ha.py -> <工作区>/payload.py` 时目录检查通过、工作区预埋代码被正常加载注册。「防聊天内容经 fs_write 预埋代码，启动即执行」的声称防线（模块 docstring 与 docs/features-skills.md）在此形态失效。利用前提是有人创建 symlink（缺省 medium 档 LLM 工具面做不到——fs.write 只写普通文件、白名单无 `ln`、tar 解出 symlink 即废弃），但「用 symlink 组织技能文件」是部署者真实用法。

**修复建议**：加载循环内逐文件 resolve 后做同款工作区检查并 WARNING 跳过，或简单 fail-closed：`path.is_symlink()` 即跳过；docs 边界描述补一句。

### M2｜【已复现（实读）】`.env.example` 为 `AGENT_NPM_GLOBAL_PACKAGES` 预置未注释活值——「登记即授权」被示例值代行

`.env.example:361` `AGENT_NPM_GLOBAL_PACKAGES=deepseek-ai/dsh` 为未注释活值；同文件「空=功能关闭」键的惯例是注释示例（如 `:210` AGENT_SSH_HOSTS）。`cp .env.example .env` 起步的部署一旦配置 SUPERUSERS（缺省 medium 档），npm_update 即注册且登记表**预置了一个具体第三方包**——该包作者并非部署者。非直接漏洞（还需 LLM 主动调用 + 本机 npm），属部署默认面问题。

**修复建议**：改为注释行 `# AGENT_NPM_GLOBAL_PACKAGES=deepseek-ai/dsh`，注释文字不动。

### M1-线2｜【推演+代码确认】skill done 按 `Error:` 前缀判错误态——run_shell 正常输出误判，且把返回正文落进日志

`agentcore/loop/engine.py:1021-1040` 的 `_done` 对 `text.startswith("Error:")` 记 `error: <正文前 120 字>`。`shell_skill.py:96` 是 `return text or "(无输出)"`——bash stdout 首行以 `Error:` 开头（`python3 x.py` 报错等极常见）时：① 成功被误记为 error；② docs/operations.md 耗时日志节承诺「只记字符数，不落返回正文」，此路径把正文写进 INFO 日志落盘。功能不受影响（`_is_permission_denied`/unknown 判定在 `_done` 之外，不毒化）。

**修复建议**：registry.execute 返回结构化结果（`(ok, text)`），或前缀判定只认 registry 兜底/技能约定的固定模板（与 `_PERMISSION_DENIED_RE` 同思路），run_shell 结果不参与前缀判定。

### M2-线2｜【推演+代码确认】`total` 起点写在 `build_payload` 之后——最慢的组装段漏计，与「从收到消息算起」声称不符

`plugins/qq_agent_adapter/matcher.py:285-288` 在 `payload = await build_payload(...)` **之后**才写 `payload["_recv_monotonic"]`。build_payload 内含图片下载（pipeline.py 既有注释「最长 30s」）与引用/转发解析，这段耗时既不进 engine 也不进 total 且无任何日志——图片消息的 total 可低估数秒到 30 秒，与 commit message 及 docs「从收到消息算起」的定义不符。

**修复建议**：`handle_chat` 开头取 `recv_at`，build_payload 返回后写入；或接受现口径但把 docs/commit 描述改为「从 payload 组装完成算起」。

### M-线4｜【已复现（线1 注入时钟直跑）】MAX_WAIT「等满放行」分支并不打 WARNING——97692c3 修复自引入的新漂移

## 2. 被证伪的发现

1. **「自定义技能可绕过权限级别过滤注册 high 级技能」——排除**：级别过滤只约束仓库内置技能注册路径；自定义技能是部署者任意代码（本有完整进程权限），对其套级别过滤无意义；`read_only=False` 默认只影响引擎并行决策，不授予能力。
2. **「GitHub shorthand 校验正则有注入面/ReDoS」——对象不存在**：匹配是纯字符串集合精确相等，无正则。
3. **「tar 侧同型通配门」——证伪**：GNU/busybox tar 都不对 `-f` 操作数做 glob；`unzip a.zip b.zip` 第二参数是成员模式非第二 archive；zip 成员通配 `unzip a.zip '*'` 落盘为条目表子集（清理超集）；busybox unzip 无 archive glob（exe 身份由宿主 `shutil.which` 决定，本机为 Info-ZIP）。
4. **「-d/-C 取值 glob」「解压输出目录 glob」——证伪**：解压器不对输出目录 glob。
5. **「此前全仓日志点无一记时」（035ed5c）——作为全仓断言证伪**：035ed5c^ 已有 embedding 进度/完成计时（`client.py:236-265`）与 ssh `elapsed=`（`ssh_skill.py:288-294`）；限定到主链路（LLM step/工具/回合）则成立。同 commit「registry.py:144」实为 `:146`（行号漂移，无实质影响）。
6. **「JSONL 备份警示漏了 persona_growth」——证伪**：它是 `user_state` 的列非独立表，随 7 表白名单覆盖；features-community 四表名单与实现一个不多一个不少。
7. **「checkout@v5/setup-python@v6 兼容性坑」——排除**：最低 runner v2.327.1（托管 runner 自动满足）；升级后两次 push 的 CI 实跑 success（GitHub API 实查）。
8. **「README 大重构丢必配说明」——大体排除**：原版 139 个 env token 在新文档体系 0 MISSING；关键非 env 段落确认迁移；仅 License 正文段未保留（最轻量，不计）。
9. **「ER 图新列/索引名写错」——证伪**：与 `store.py` DDL 逐列逐索引比对零误差（含 schedules_due_idx 与「sessions_user_scope_key 刻意不在 DDL 建」的描述）。
10. **「_recv_monotonic 泄漏进 prompt/存储/渲染」——排除**（线2 逐字核实五条路径：`_run_and_format` 白名单 context、engine 只 `context.get` 特定键、payload 从未入 store、merge_parts 只读白名单键、群环形缓冲走独立 recorder）。
11. **「sys.modules 被自定义技能污染」——排除**：`spec_from_file_location`+`exec_module` 全程不写 sys.modules、不加 sys.path（线1 实跑验证：加载 stem 为 `os` 的文件后标准库完好）。
12. **存疑未立案**：parser differential（tarfile vs GNU tar 对畸形头）与 TOCTOU（扫描与解压间换包，受工具并发闸约束）——超出本轮只读边界，留专项；解压期 symlink 穿透写窗口为 L18 既有披露项，未重复立案；run_shell stdout 恰以 `Error: unknown skill` 开头理论上会误增 `unknown_calls`（概率极低、非本次改动，仅记录）。
