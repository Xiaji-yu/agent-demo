# FIX 记录：群发文件私发 / 自身消息自触发 / 空文本复用历史图

来源：用户线上报告（非评审轮次），三个现象一条因果链：

1. 群里让 bot 发文件 → **私发**到请求者
2. 私发的文件消息**触发了对话**（用户全程没说话）
3. 触发的这轮对话是**历史记录中一张图的解析**

根因链：`send_markdown_file` 只有私聊实现（群上下文被 registry 按签名丢弃）
→ 群文件永远私发；NapCat「上报自身消息」把 bot 私发的文件作为 message 事件
回传（`user_id == self_id`）→ 私聊分支无条件触发 → 回传的文件消息无文本段
→ pipeline 复用 recent_images 里的历史图 + 填"（请结合用户发来的图片回答）"
→ 多模态请求 → 模型解析旧图；且 bot 的回复再次回传，存在自循环。

## 追加：群聊上下文注入边界收紧（同批工作区改动）

来源：用户线上报告——群友各聊各的时，用户引用其中一条消息/图片提问，
模型把群里不相干的聊天也当上下文，反而被带偏（群流从「帮模型理解语境」
沦为噪音）。

### M4 引用/转发时不附群聊上下文（Medium）
- `plugins/qq_agent_adapter/pipeline.py`：群流注入门控由
  `if group_id and context_enabled()` 收紧为
  `... and not has_quote and forward_id is None`——被引/转发内容本身已进
  extra_context（最强语境信号），群友各聊各的时再叠加整个群的消息流只会
  引入无关话题。无引用的裸唤醒（「他们刚才聊啥」）才附群流。与 has_reply
  挡最近图片复用（同文件 reuse_ok）同一设计哲学。
- 直接发图（无引用）场景**保持现状**（仍附群流）：图没有文字语境，群流是
  合法补充；且空文本复用已由上批修复挡掉。
- 不加配置开关：与 has_reply 挡最近图片的先例一致（行为确定性优先）。
- 回归：`TestGroupContextAttachment` 3 条（reply 不附 / forward 不附 /
  无引用照常附）；变异复核：回退门控后 2 条收紧用例失败。
- 文档：README 群上下文章节 + group_context.py docstring 同步行为边界。

### L4 .env 泄漏 AGENT_IMAGE_* 污染 media 测试（Low，M1 同模式）
- 用户 .env 设 `AGENT_IMAGE_ALLOW_ANY_HOST=1`（部署放开图片域名白名单），
  经 conftest 的 load_dotenv 泄漏进测试会话 → `TestMediaUtils` 4 条
  fail-closed 断言假失败（verified：复现后修复）。
- `tests/test_media.py`：新增模块级 autouse fixture `_clean_image_env`
  （delenv AGENT_IMAGE_HOSTS / AGENT_IMAGE_ALLOW_ANY_HOST）；需要放开白名单

## 追加：人格注入模板优先级 + 搜索触发扩展（同批工作区改动）

来源：用户反馈"人格体现很差"——实测（stepfun API 对照实验）定位为模板结构
问题：人格段之后紧跟无条件通用声明"你是一个有帮助的 AI 助手"，人格弱时模型
被拉回标准客服；且工作流全是功能指令、无任何"怎么说"的约束。

### M5 persona 优先于通用助手声明（Medium）
- `agentcore/loop/engine.py` `_build_system_prompt`：
  - persona 存在时**去掉**"你是一个有帮助的 AI 助手"，注入话术改为
    「贯穿本次对话的每一条回复，包括工具调用后的最终回复；语气、口吻、
    自称方式始终遵循此人格，优先于任何通用助手身份」
  - 工作流之后追加（仅 persona 存在时）「以上工作流只规定做什么，回复的
    语气、口吻与风格始终遵循人格设定」
  - 无 persona 时通用声明与旧行为完全一致
- 端到端实测（真实模板 + fortune_teller）：身份问句从"说明书腔"
  （"我是一位……大致分两种情况"）变为对话感（"我是你的玄学顾问……
    把我当成一个说话不绕弯子的朋友"）；非玄学话题也保持角色连贯性。
- 回归：3 条（persona 去通用声明+话术+语气约束 / 无 persona 保持通用声明 /
  搜索措辞守卫）；变异复核：回退模板后 2 条收紧用例失败。

### M6 语境差异过大时主动搜索补全（Medium）
- 工作流第 1 条扩展：用户明说搜索时优先 search_web（原语义保留）；**新增**
  当问题与当前对话语境差异过大、缺乏背景无法准确回答时（话题切换、陌生概念/
  新鲜事件、无法从对话与记忆理解指代），应主动调用 search_web 补全，
  不要凭记忆硬答；纯常识/观点/闲聊不搜索。
- 与群聊上下文收紧联动：引用场景模型缺少背景时，"引用内容不可读"告知之外
  多了一条主动补全的出口。
- 回归：`test_search_triggered_on_context_gap`（措辞守卫）。
- README 人格系统章节同步注入方式与"全程扮演 vs 话题触发"的设计惯例。

## 追加：回答优先级链 + 搜索时效性（同批工作区改动）

来源：用户反馈两件事——(1) 期望工作流优先级为「本地 RAG → 大模型 →
联网搜索」，现状模板把 search_web 放在最显眼位置、无优先级声明；
(2) 搜索时效性差，query 常带「2025」搜回过时新闻。

### M7 当前日期注入 + 本地优先优先级链（Medium）
- `agentcore/loop/engine.py` `_build_system_prompt`：
  - 注入「今天是 YYYY 年 M 月 D 日」（datetime.now）——模型内部知识有截止
    时间，生成 query 时会沿用训练数据的旧年份，日期锚点是 query 约束的前提
  - 工作流第 1 条改为优先级链：先基于长期记忆/知识库（本地检索）与对话上下文
    回答；本地不足/过时/需最新信息时才 search_web；冲突时以更新更具体的来源
    为准；query 不写死历史年份（除非用户明确问某一年）、用相对表述、结果按
    发布日期优先取新
  - 「语境差异过大主动补全」的规则（上批 M6）保留为第 1 条后半
- 端到端实测（真实模板 + 真实 tavily）：prompt 含日期与优先级；时效性问题
  返回 2026 年当下内容，无旧年份污染。
- 回归：`test_today_date_and_local_first_priority`（措辞守卫）+ 上批
  `test_search_triggered_on_context_gap`；变异复核：回退模板后均失败。

### M8 搜索结果带发布日期（Medium）
- `agentcore/skills/search.py`：`_items_bocha`/`_items_tavily` 提取
  `date`/`published_date`（此前被丢弃），`_norm_date` 归一为 YYYY-MM-DD，
  `_fmt_item` 在标题后标注（发布日期）——模型据此核对时效、优先取新。
- skill description 同步时效性约束（query 不写死年份）。
- 回归：`TestSearchDate` 4 条；变异复核：回退后 4 条全失败。
- 已知边界：tavily 对聚合主页类结果无 published_date（数据源特性），
  新闻文章类结果正常带日期（单测覆盖提取逻辑）。

## 追加：Markdown 表格渲染成图片（同批工作区改动）

来源：用户实测反馈——对比类回答以 MD 表格发出时，QQ 聊天框不渲染 Markdown，
竖线错位、整段不可读（原话："观感非常差，能不能加个 skill 把表格转化为图片"）。

### M9 表格 → PNG 渲染与投递（Medium）
- `agentcore/render/table.py`（新模块，纯 Python）：`split_tables` 提取 MD 表格块
  （连续 `|` 行 + 第二行分隔行，单行竖线与缺分隔行的文本不误伤）；`render_table_png`
  用 Pillow + 文泉驿中文字体（data/fonts/wqy-zenhei.ttc）渲染（表头灰底、网格线、
  左对齐、超宽自动缩字号/截断加省略号、宽上限 1600px）；无可用字体返回 None。
- `plugins/qq_agent_adapter/outbound.py`：`deliver_reply` 最前面插入表格处理——
  表格渲染为 PNG 以 base64:// 图片消息先发（过同一进程级节流），剩余文本继续走
  原有分层；渲染失败时表格拼回文本（顺序会变但内容不丢）；新增
  `AGENT_TABLE_TO_IMAGE=1` 开关与 `table-image` 投递模式。
- 与「长回复不渲染成图」的设计不冲突：图的粒度是**表格块**（结构化数据，
  本就不可选中/搜索），不是整段文字。
- 回归：`test_table_render.py` 10 条（提取边界 6 + 渲染 4）+ `test_outbound.py`
  `TestTableToImage` 5 条（仅表格/文+表/私聊/渲染失败降级/开关关闭）；变异复核：
  split 失效 2 条失败、render 恒 None 2 条失败、outbound 集成回退测试无法收集。
- 结构验证（程序化，当前模型无图片输入）：行高精确（5 行=160px）、表头灰底存在、
  非白像素 11.5%、窄表宽度自适应（68px）。
- 文档：README 出站分层章节 + .env.example 同步 `AGENT_TABLE_TO_IMAGE`。
