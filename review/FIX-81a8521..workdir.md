# FIX 记录：群发文件私发 / 自身消息自触发 / 空文本复用历史图

来源：用户线上报告（非评审轮次），三个现象一条因果链：

1. 群里让 bot 发文件 → **私发**到请求者
2. 私发的文件消息**触发了对话**（用户全程没说话）
3. 触发的这轮对话是**历史记录中一张图的解析**

根因链：`send_markdown_file` 只有私聊实现（群上下文被 registry 按签名丢弃）
→ 群文件永远私发；NapCat「上报自身消息」把 bot 私发的文件作为 message 事件
回传（`user_id == self_id`）→ 私聊分支无条件触发 → 回传的文件消息无文本段
→ pipeline 复用 recent_images 里的历史图 + 填"（请结合用户发来的图片回答）"
→ 多模态请求 → 模型解析旧图；且 bot 的回复再次回传，存在自循环。

## 逐项修复

### M1 `send_markdown_file` 无群文件路径（Medium）
- `agentcore/skills/file_sender.py`：新增 `_safe_group_id`（与 `_safe_user_id`
  同规格，防全角群号）与 `_send_group_file`（OneBot `upload_group_file`，
  base64:// 承载）；`send_markdown_file` 增加 `group_id` 参数，非空走群分支。
- 三态纪律与 outbound `_send_file` 一致：OK / UNCERTAIN（超时断连不重发）/
  **确定失败不降级私发**——用户明示要文件时静默私发会把文件送到错误的地方
  （正是本次线上现象的根因），改为返回失败原因由上层转告。
- skill handler 签名加 `group_id`，`registry.execute` 按签名注入
  （engine 侧已在调用前剥掉 LLM 幻觉的 group_id，注入的是真实值）。
- 回归：`TestGroupFile` 6 条（群文件走 upload_group_file / 确定失败不回退私聊 /
  超时 UNCERTAIN / 非法群号拒绝 / `_safe_group_id` 白名单 / registry 注入链路）。

### M2 无 self 消息过滤，私聊无条件触发（Medium）
- `plugins/qq_agent_adapter/matcher.py`：新增 `_is_self_message`
  （`user_id == self_id` 判据），`trigger_rule` 开头过滤；`group_recorder`
  的 rule 同样过滤——bot 的发言不是「其他群成员」的语境。
- self_id 缺失（空串）时不过滤任何消息，防御性回退安全。
- 回归：3 条（私聊 self 拒绝 / 群聊 self 含唤醒词也拒绝 / group_recorder 拒绝 self）。

### M3 空文本消息复用最近图片（Medium）
- `plugins/qq_agent_adapter/pipeline.py`：`reuse_ok` 增加
  `bool(user_text.strip())` 约束——纯 file/表情段消息（含 NapCat 回传的
  自身消息）没有"追问"，塞历史图等于答非所问。
- 纯文本追问复用不受影响（设计行为保留，`test_private_still_reuses` 守卫）。
- 回归：`test_empty_text_message_does_not_reuse`。

## 遗留项（本批未修，不在报告范围）

- **auto file fallback 与模型 tool call 双路径可能重复发文件**：用户文本命中
  「文件/文档」等关键词时，matcher 兜底会执行一次 `send_markdown_file`，
  无法区分模型本轮是否已自行调用过该 skill（engine.run 只返回最终文本）。
  极端情况下用户会收到两个文件（内容不同的两份）。彻底修法需要 engine 返回
  结构化结果（如已发送文件标记），改动面较大，留待后续。

## 追加：群聊上下文注入边界收紧（同批工作区改动）

来源：用户线上报告——群友各聊各的时，用户引用其中一条消息/图片提问，
模型把群里不相干的聊天也当上下文，反而被带偏（群流从「帮模型理解语境」
沦为噪音）。

### M4 引用/转发时不附群聊上下文（Medium）
- `plugins/qq_agent_adapter/pipeline.py`：群流注入门控由
  `if group_id and context_enabled()` 收紧为
  `... and not has_quote and forward_id is None`——被引/转发内容本身已进
  extra_context（最强语境信号），群友各聊各的时再叠加整个群的消息流只会
  引入无关话题。无引用的裸唤醒（「他们刚才聊啥」）才附群流。与 has_reply
  挡最近图片复用（同文件 reuse_ok）同一设计哲学。
- 直接发图（无引用）场景**保持现状**（仍附群流）：图没有文字语境，群流是
  合法补充；且空文本复用已由上批修复挡掉。
- 不加配置开关：与 has_reply 挡最近图片的先例一致（行为确定性优先）。
- 回归：`TestGroupContextAttachment` 3 条（reply 不附 / forward 不附 /
  无引用照常附）；变异复核：回退门控后 2 条收紧用例失败。
- 文档：README 群上下文章节 + group_context.py docstring 同步行为边界。
